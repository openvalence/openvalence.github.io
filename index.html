Open-source hardware and software for linear motion machines

For OSSM-style machines and anything else that moves along a rail. The firmware runs a hub that holds the machine's state. The desktop app, browser tabs, scripts and plugins connect to the hub as clients and stay in sync with it. The board, its firmware, the protocol and the client are published under MIT, CC BY 4.0, Apache-2.0 and CERN-OHL-S-2.0.

The client

Phosphor is the reference client. Phosphor builds its pages from the settings the hub declares; a setting added in the firmware appears in Phosphor without a Phosphor update. Plugins draw their own controls over the same protocol. It has a built-in Virtual machine, the hub firmware compiled to WebAssembly, so Phosphor runs with no hardware attached. More on Phosphor.

Status

The firmware homes the rail, plays scripts, and connects to the client over Wi-Fi. Phosphor builds for Windows, macOS and Linux from one codebase. The protocol is pre-release: it changes through RFCs, and the registry assigns every wire number. The docs cover building clients and machines; Phosphor's plugin contract covers building control surfaces.

How it's built

One person designs this and makes every decision; coding agents write most of the code under that direction. Each repo holds its rules: a written doctrine, a registry that assigns every wire number, lint that fails the build, tests on every change, and a bench gate that requires firmware to move a real motor before a change is closed.
