How it fits together

The firmware runs a hub that holds the machine's state. The desktop app, browser tabs, scripts and plugins connect to the hub as clients and stay in sync with it. Here's the path from your screen to the rail.

  1. Phosphoror any app

    The app. Phosphor builds its pages from what the machine declares. Scripts, plugins and the page the machine serves connect the same way. Phosphor

  2. Valencethe protocol

    The wire. WebSocket over Wi-Fi, BLE for setup. The machine describes itself; apps send requests. Valence

  3. ESP32-C6radio

    The radio. Moves bytes over SDIO and runs Espressif's stock image, none of our code. So you only ever flash one chip. Chips

  4. HubNucleus on the ESP32-P4

    The hub. Holds the only real state, clamps every request to the machine's limits and tells every app what it actually did. Nucleus

  5. Kinetic²planner

    The planner. Turns timed knots into a 128 ms strip of positions on a 1 ms grid. So a short planner stall never reaches the motor. Kinetic

  6. LP corequadrature out

    The LP core. Sends A/B quadrature from a 40 MHz crystal and parks itself if its 4 ms lease runs out. Motion

  7. Servo drivecloses the loop

    The drive. Follows the quadrature and closes the loop on the motor. Alarms come back to the P4, RS485 carries reads. Drive interface

  8. Motor and railwhere it ends up

    The rail. The firmware homes it and holds every move inside the rail window; the PCB's E-stop cuts motor power in hardware. Hardware

  9. Hover or tap a block. Blue is motion going out; the hub is the one in charge.

The parts

  • Valence

    The protocol: spec, registry, reference library, clients, tools, documentation.

    MIT · spec text CC BY 4.0

  • Nucleus

    Firmware for the OSSM Flagship PCB: an ESP32-P4 with an ESP32-C6 for Wi-Fi, built on ESP-IDF. The P4's low-power (LP) core generates the quadrature output.

    Apache-2.0

  • Phosphor

    The reference client, for Windows, macOS and Linux (including a Flatpak), with plugins, themes and a built-in Virtual machine. Android is WIP.

    Apache-2.0

  • Kinetic

    The motion planner: jerk-limited trajectories from timed knots. Header-only C++, deterministic across targets.

    Apache-2.0

  • Hardware

    The OSSM Flagship PCB and everything physical around it, in KiCad.

    CERN-OHL-S-2.0

  • Isotope

    Accessory firmware for the ESP-NOW network around Nucleus. WIP: design stage, nothing runs yet.

    no license yet

  • ButtplugIO

    A fork of buttplugio/buttplug carrying the Valence hardware manager, on branch valence.

    BSD-3-Clause

The docs cover building clients and machines; Phosphor's plugin contract covers building control surfaces.

How it's built

One person designs this and makes every decision; coding agents write most of the code under that direction. Each repo holds its rules: a written doctrine, a registry that assigns every wire number, lint that fails the build, tests on every change, and a bench gate that requires firmware to move a real motor before a change is closed.
