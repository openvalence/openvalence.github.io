Nucleus

Nucleus is the firmware for the OSSM Flagship board. It runs the Valence hub, plans the motion and generates the quadrature signal that steers the servo drive. It is built on ESP-IDF and licensed Apache-2.0.

Status bench

Works on the bench, not in the field yet. It runs on an ESP32-P4 dev board and bench rigs; a finished Flagship board does not exist yet (see Hardware). There is no release and no download. When there is one, it will be on Downloads.

Chips

The ESP32-P4 runs everything we wrote: the Valence hub, the WebSocket server, policy and motion. The ESP32-C6 is a Wi-Fi and BLE radio on an SDIO link, running Espressif's stock esp_hosted image. So there is no radio firmware to build or flash: you only ever flash the P4.

A CH32V003 board monitor runs its own small firmware, programmed by the P4 and carried inside the Nucleus update. So one update covers both chips.

Motion

The planner, Kinetic², keeps a strip of the next 128 positions in mm, one per 1 ms tick. So a planner solve of up to 128 ms never leaves the steer without a plan. Past the end of the strip the steer holds the last position and counts a planner stall.

Every 1 ms tick the steer reads the strip and gives the LP core three things: a velocity, a fence and a lease renewal. The fence is a pair of edge counts that no edge may cross. The lease is a 4 ms timer.

If the lease is not renewed for 4 ms, the LP core parks itself and counts a lapse. So a stalled main core can keep the carriage moving at its last speed for 4 ms at most.

A Wi-Fi hiccup is a separate problem with a separate cover. The client sends segments up to the schedule horizon minus 100 ms ahead, which is 900 ms at the factory horizon of 1000 ms. So a Wi-Fi stall shorter than that lead never reaches the motion.

The LP core emits A/B quadrature edges, and its signed edge count is the machine's position. Its poll loop is 5 cycles, 125 ns at 40 MHz, and every edge lands on that grid. Measured at a prime edge rate on a Rigol DHO4204, the spread is 128 ns peak to peak and the rounding does not accumulate. So timing error stays inside one 125 ns step and never adds up over a stroke.

The LP core runs from its own SRAM. While the main cores erased and wrote flash with the cache off, a scope saw 2,156 transitions and 0 illegal ones. So saving settings does not glitch the motor signal.

Safety

The MotionArbiter is the only code allowed to command motion. Manual input, scripts, patterns and network sessions submit intents to it. So every safety check lives in one place: homed, commissioned, pause, e-stop, and a clamp to the rail window.

The E-stop input is read first on every 10 ms pass and latches an e-stop in the hub. On the board, the same button also cuts motor power in hardware. So an e-stop does not depend on the firmware being healthy.

Pairing WIP

A single press of the PAIR button opens a 120 s pairing window. A double press approves the one pending request for configure access. Holding it for 5 s drops every paired client to watch access and ends their sessions. So you can pair, approve and lock out clients from the button alone. These gestures are in draft RFCs and may change.

Boot with PAIR held and the board enters config mode: BLE and USB serial only, no Wi-Fi, and the first client to connect gets configure access. So you can set up a board that has no network. The access tiers are in the Valence docs.

Updates

An HTTP POST to /ota on port 80, with a token, writes the new image to the idle slot and reboots. The new image is on trial: if its hub task hangs before it proves itself, the watchdog resets the board and the bootloader brings back the previous image. So a bad update does not brick the board.

How it fits

Nucleus is the hub in Valence: it holds the machine's state, and clients such as Phosphor send intents that it clamps and echoes. Kinetic is pinned by commit, and the board it runs on is Hardware. The same hub code compiles to WebAssembly and runs inside Phosphor as the Virtual, so you can try it with no board; see Demos. The diagrams show the whole system, and Components lists every part.
