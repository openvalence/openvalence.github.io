Valence is the web for motion machines

The machine serves its own control panel, and any app can open it.

The short version

You already know how this works. You type an address, a server sends a page, your browser draws it. The server doesn't care which browser you use. Valence does the same job for a machine.

On the webIn Valence
WebsiteThe machine. Its firmware runs a hub that holds the machine's state.
BrowserThe app. Phosphor, a script, a plugin, a hardware remote. Any number at once, all kept in sync.
HTTP and HTMLValence: the wire format, plus the catalog the machine sends to describe itself.
Server-side checksMachine-side limits. The machine checks every request, whatever the app thinks.

The one difference

A website sends a finished page. A Valence machine sends a description: what each setting is, its units, its range, and who may change it. No layout, no colors, no widget hints. The app decides how it looks.

So a setting added in the firmware shows up in every app the next time it connects, with its label, units and limits. Nobody ships an app update for it.

Why safety lives in the machine

Your app is one client of many, and any client can be wrong: an old version, a buggy plugin, a script with a bad number in it. So the machine trusts none of them.

  • The machine holds the only real state. Apps send requests. The machine clamps each one to its limits and tells every app what it actually did.
  • One component on the machine drives the motor. Every request goes through it. There is no side door.
  • If an app goes quiet, it loses control of motion. The default is 600 ms.
  • Anyone connected can stop the machine, even an app that is only watching. Starting it takes control access. The spec puts it this way: "you may always stop the machine; you may not always start it."
  • A hardware e-stop is still the last word. The protocol's stop is a convenience, not a replacement for one.

Who can do what

Every connection has an access tier. Watch sees everything and can stop the machine. Control can also move it. Configure can also change setup and decide who else gets in. Watching needs no pairing; the rest does. The pairing diagram shows how you get each one.

What's in the repo

The spec
The protocol, in one document, plus the registry that assigns every wire number. CC BY 4.0.
The library
A C++20 reference implementation. Header-only, no hardware, no dependencies. MIT.
Clients
A JavaScript client and Valence Connect, a plugin for MultiFunPlayer.
Valence Bench
A reference hub that runs with no hardware, for testing a client.
Tools
A wire-level conformance probe, a tracer, a soak tester.

Status: pre-release. The spec is v1.0-draft and changes through RFCs. Wire numbers are not frozen yet. The name "Valence" is reserved for implementations that pass conformance.
